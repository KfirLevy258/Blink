**BLINK 1.3.4 is about setting up.** It now installs on Windows on Arm, and `blink install` and `blink status` describe the computer they are actually on. They used to tell some desks they were missing things they already had.

## What changed

- **Windows on Arm works.** Newer Windows laptops with Arm processors were told the USB driver had "failed", or that no driver existed for them. BLINK now ships the board's Arm64 driver and installs it, so the board connects there like on any other Windows computer.
- **Install and status describe your desk.** With Claude Desktop and no Claude Code, `blink install` said the panel would have no countdowns and no activity light. It gets the five-hour countdown from Desktop, and the light works in Desktop's Code tab. Install and status now check what is on the computer once and report only that.
- **A Claude Desktop that is not signed in yet is no longer called "not installed".** It is told to open Desktop and sign in, which is all it needs.
- **Status trusts a live reading.** On a computer where Claude Code runs outside the usual path (an IDE's own copy, say), `blink status` could ignore a reading that was arriving right now.
- **A licence that says what we mean.** BLINK's code was under MIT, which allows selling copies. It is now PolyForm Noncommercial, with an exception for using BLINK at work. Building one for your own desk, at home or at your job, is fine.

The board itself has no changes in this release. It shows 1.3.4 after updating so the two halves agree.

## Updating

Run **`blink update`** to install this version, then the screen offers the firmware and one tap installs it.

Automatic app updates are off for this release, so nothing installs on its own.

Something wrong? Email **support@blink-buddy.com** with the output of `blink status` and the last lines of `bridge.log`.
