**BLINK 1.4.0 adds OpenCode.** OpenCode now gets its own page beside Claude and Codex, and joins the activity light. With a GLM Coding Plan it shows the plan's real quota. With any other model, including one you host yourself, you can set a token budget and the dials show your use against it.

## What changed

- **OpenCode, on its own page.** On the GLM Coding Plan (Z.ai, or BigModel in mainland China) the dials show the plan's 5-hour and weekly quota with both countdowns, the same way they show Claude's and Codex's. Plans bought before July 2026 report in an older format, and those work too.
- **OpenCode joins the activity light.** Amber while an OpenCode session waits on a permission prompt or a question, a green pulse while it works, and red when a turn fails. `blink install` adds one small plugin file to OpenCode's plugin folder for this, and `blink uninstall` removes it. It works with OpenCode 2.0 and with OpenCode 1.3.4 or newer. If OpenCode was used in the last hour and the light saw nothing, `blink status` says so and tells you to restart OpenCode.- **A token budget for any other model.** OpenCode does not record a limit for a model it reaches through anything other than a plan, so until now the dials stayed at `--%`. Run `blink opencode-budget 5h=2M 7d=20M`, using any numbers you like, and the dials show OpenCode's own token count against them over the last 5 hours and the last 7 days. These are rolling windows, so there is no countdown. Run `blink opencode-budget` on its own to see the budget and what you have used, and `blink opencode-budget off` to drop it. The panel picks up a change within a few seconds.
- **Three providers, three pages.** On the new firmware every provider with a figure gets its own page, in a fixed order: Claude, Codex, OpenCode. The same tap always reaches the same page. Tap the name at the bottom, or swipe up or down, to step through them. A board you have not updated yet keeps two pages, and the second follows whichever of Codex and OpenCode you used last.
- **Windows on Arm works.** Snapdragon laptops and the Surface Pro X now get the Arm64 build of the USB chip's driver. Before, `blink install` reported that the driver failed. This was tested on Windows 11 on Arm with a real board.
- **`blink install` and `blink status` describe your machine as it is.** A Claude Desktop that is installed but not yet signed in was reported as not installed. A Desktop-only machine was told it lacked a countdown and an activity light it already had. A status line that was live was hidden when `claude` was not on your PATH. Both commands now check your machine once and report only what they find.
- **The licence now says what was always meant.** BLINK is free to build and use for yourself, including at work. It is not free to sell. MIT allowed selling, so it was replaced by PolyForm Noncommercial, plus an exception for using BLINK at work.

## Privacy

BLINK reads figures Claude Code and Codex already write to your disk and sends nothing anywhere. OpenCode on the GLM Coding Plan is the one exception, because OpenCode never writes its limits down. BLINK reads the Coding Plan key that OpenCode already saved, read-only, and asks the plan's own usage endpoint for your quota. It asks about once a minute while you use OpenCode, every ten minutes otherwise, and not at all after a week without OpenCode. A token budget reads only OpenCode's token counts: when each reply was made, which provider answered, and how many tokens it took. It never reads the text, and nothing is sent anywhere.

## Updating

Run **`blink update`** to install this version. The screen then offers the firmware, and one tap installs it. The third page needs the firmware. Everything else works as soon as the app updates.

Something wrong? Email **support@blink-buddy.com** with the output of `blink status` and the last lines of `bridge.log`.
