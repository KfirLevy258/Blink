# Spend Page Implementation Plan (Plan A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a usage-based Claude seat, the Claude page shows the month's spend against the cap, exact after `/usage` and estimated between, with a dollar burn view, without BLINK ever starting Claude Code.

**Architecture:** One parse of Claude Code's config gives plan, seat, account fingerprint and the saved usage (`pc/claude_plan.py`). A persisted running count of status-line cost rises (`pc/spend_count.py`) fills the gaps between `/usage` runs. `pc/providers/claude_cli.py` builds a spend frame; the ingest bus treats the config as authoritative for the Claude page. Board side and the `plan` message come from the unmerged `fp/enterprise`, rebased onto main.

**Tech Stack:** Python 3.11+ stdlib (`pc/`), Zephyr 4.3 / LVGL 9 firmware, pytest, firmware host tests, `tools/panel_render`.

**Spec:** `docs/plans/enterprise-spend.md` (revision 3), sections 1-3 and 5.

## Global Constraints

- `pc/` stdlib only. Every serial writer uses `protocol.encode_checked()`; lines ≤ 512 bytes.
- Never print or log spend figures, seat fields, account ids or text from Claude Code's files. `pc/` prints to stderr, so log tests use `capfd` (and `caplog`).
- BLINK never starts `claude`, never contacts Anthropic, keeps no raw account id (fingerprint only).
- Cache amounts are minor units (cents); only `currency == "usd"` is used.
- The period is the calendar month starting 00:00 UTC on the 1st.
- Fixtures are generated by committed code; no measured values from a real seat.
- Paths resolved inside functions. Firmware `BOARD_CAPS` append-only.
- Board copy: sentence case; glyphs only from the built fonts (`$ . , ~ + •` present; `·` absent). Widest digit in montserrat is `4`; width tests use it.
- Firmware is done when flashed with `tools/burn.sh` and boot-verified.
- Commits: plain subject, prose body, no trailers; `git config core.hooksPath .githooks`.

## Review Focus

1. `/login` Enterprise → Max → Enterprise, including with the daemon stopped between: spend mode follows the seat at once and the count restarts at zero for a different fingerprint (Tasks 2, 3).
2. A daemon running across 00:00 UTC on the 1st with an unchanged config: the figure drops to the new month (Task 4).
3. A seat that never ran `/usage`: the page shows the count from zero as an estimate with the hint, through the whole bus, never "Not reported" (Task 4).
4. A fresher Claude Desktop windows sample on a spend seat: the page stays a spend page (Task 4).
5. A saved no-window verdict from an earlier Ultra login: a spend page is never marked and never gets the token burn view (Task 4).
