# Claude Code Inside WSL Implementation Plan (Plan B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `blink install --wsl <distro>` makes a Windows desk read Claude Code running inside one named WSL distribution, with the board on Windows, touching WSL only while the user is using it.

**Architecture:** A `ClaudeHome` record (native, or one WSL distribution recorded at install) tells readers and installers where Claude Code's files are. `pc/wsl.py` wraps the registry and `wsl.exe`. The WSL shims write into a Windows folder the daemon owns, so the 2 s poll never touches WSL; colder reads run in a `WslWatch` worker thread behind a "running and in use" gate. **Depends on Plan A Tasks 1-2** (`claude_account` exists and takes its fields from `PlanReader.look()`).

**Tech Stack:** Python 3.11+ stdlib (`winreg` imported lazily, `subprocess`, `threading`), POSIX sh shims, pytest.

**Spec:** `docs/plans/enterprise-spend.md` (revision 3), section 4.

## Global Constraints

- Never automatic: no registry read, `wsl.exe` call or UNC access unless the user runs `blink install --wsl` or a WSL home is recorded.
- No test starts the real `claude` or `wsl.exe` (Task 1).
- `wsl.exe` is called by absolute path (`%SystemRoot%\System32\wsl.exe`), with `pc/ota.NO_WINDOW` (a dict, empty off Windows), binary pipes, all three std handles, a timeout, and `WSL_UTF8` set explicitly in the child environment ("1" = UTF-8; anything else = UTF-16LE without BOM).
- Commands into Linux use `-d <name> [-u <user>] -e <argv...>`, never `--`.
- A distribution is identified by its registry GUID.
- Nothing from the probe is printed or logged; error messages on WSL paths are scrubbed of the path. Proxy and certificate variables are not stored.
- Installers default to the native home; only `--wsl` writes into WSL.
- Commits: plain subject, prose body, no trailers.

## Review Focus

1. A plain `blink install` on a Windows machine whose WSL is used for other work: no registry read, no `wsl.exe` (Task 6).
2. `wsl --shutdown` while the daemon runs, then the user opens WSL again: reads stop without restarting it, and resume (Task 5).
3. zsh with `claude` from nvm, and a `.zshrc` that prints a banner: the probe finds `claude` and `CLAUDE_CONFIG_DIR` (Task 3, run under real shells on macOS).
4. `settings.json` in the distribution is a symlink into a dotfiles repo: install and uninstall keep the symlink (Task 4).
5. `%USERPROFILE%` with a space and an accented letter: the drop folder and shims work (Task 4).

### Task 3: `pc/wsl.py`

**Files:** Create `pc/wsl.py`. Test `tests/pc/test_wsl.py` (fakes: `exe=(sys.executable, "<tmp>/fake_wsl.py")`, an injected registry reader, an injected runner for launch flags).

**Interfaces:**
- `Distro` (frozen): `guid`, `name`, `version`, `default`.
- `policy_blocks(reg=None) -> bool`: `HKLM\Software\Policies\WSL` `AllowWSL` equal to 0. Not `AllowInboxWSL`: that one turns off only the inbox WSL and leaves the Store WSL running.
- `distros(reg=None) -> list[Distro]`: `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss`, entries with `State == 1`. On a registry error: `[]` and the caller says to check WSL; the `wsl -l -q` names carry no GUID and are not used for install.
- `running(name, exe=WSL_EXE, timeout=5) -> bool` (`-l --running -q`, UTF-16LE).
- `run(name, argv, user=None, env=None, exe=WSL_EXE, stdin=None, timeout=30, runner=subprocess.run) -> tuple[int, bytes, bytes]`: `[*exe, "-d", name, *(["-u", user] if user else []), "-e", "env", *("K=V"), *argv]`; timeout → `(-1, b"", b"")`; argv inside Linux is wrapped in `timeout -k 5 <t>`.
- `unc(name, linux_path) -> str` (`\\?\UNC\wsl.localhost\...`; `\\wsl$\...` when `long_paths=False`).
- `probe(name, exe=WSL_EXE) -> Probe | None`: (1) `getent passwd "$(id -un)"` → user, home, shell; (2) `<shell> -lic 'exec env -0'` with stdin closed, timeout 20 s → the environment; (3) `env PATH=<captured> sh -c 'command -v claude'` (non-login) → `claude_exe`, rejected if under the automount root, falling back to `~/.local/bin/claude` then `~/.claude/local/claude` (`test -x`). `Probe`: `user`, `home`, `shell`, `config_dir` (`CLAUDE_CONFIG_DIR` or `<home>/.claude`), `claude_exe`.

### Task 5: `WslWatch`

**Files:** Create `pc/wsl_watch.py`. Modify `pc/claude_plan.py` (`PlanReader(source=...)`), `pc/ingest.py` (burn facade), `pc/install_statusline.py` (WSL drift in the watch), `claude_usage_bridge.py` (start the watch for a WSL home; no `DriftWatchdog` on the main thread for it). Test `tests/pc/test_wsl_watch.py`.

**Interfaces:**
- `WslWatch(home, running=wsl.running, clock=time.time)`, modelled on `status_page.StatusWatch` (daemon thread, `tick()` does the I/O, readers get memory under a lock):
  - `live()`: `drop_dir` newest mtime within 600 s (checked first, NTFS only) **and** `running(name)` true at a check made at most every 15 s.
  - In `tick()`, only when live: parse the config with `claude_plan.parse` (resolving the file from `home.config_dir` there) and keep the `ConfigView` (not the document); run its own `BurnReader(root=home.transcripts)` `poll`/`prune`; run the WSL drift check.
  - `view() -> ConfigView | None`; `burn_snapshot()` for the bus facade.
- The status-line payload and hook state are read from `drop_dir` directly (NTFS, no gate).
- `blink install --wsl` restarts the service so the bus is rebuilt with the watch.
